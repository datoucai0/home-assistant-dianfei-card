# 技术说明

## 为什么是 iframe，不是自定义卡片

试过三条路，按顺序被否：

| 方式 | 结果 |
|---|---|
| `markdown` 卡承载 HTML | ✗ HA 用 DOMPurify 清洗，**`style` 属性全部被剥掉**，布局与配色全塌 |
| `custom:button-card` 的 `custom_fields` | ○ 可行（走 `unsafeHTML`，内联样式保留），但它的默认 grid 布局会把内容挤到第二列，需要 `display:block` 覆盖，且多层嵌套难维护 |
| **单文件 HTML + `iframe` 卡** | ✓ 浏览器原生渲染，CSS 完全可控；同源可读父窗口 `hass`，无需令牌 |

## 数据从哪来

`state_grid` 集成把历史数据放在**实体 attributes** 里，`state` 只是最新值：

| 实体 | attribute | 内容 |
|---|---|---|
| `..._previous_daily_usage` | `daily_history` | 逐日 `usage` / `valley` / `flat` / `peak` / `tip` |
| `..._previous_settled_month_usage` | `monthly_bill_history` | 逐月 `usage` / `charge` |

这也是本项目**不需要额外容器/爬虫**的原因——数据本来就在 HA 里，只是没被读出来。

## 页面如何取值

```js
window.parent.document.querySelector('home-assistant').hass.states[entityId]
```

同源 iframe 可直接访问父窗口，用登录会话，无需长期令牌。
每 10 秒重读一次；任一实体读不到就单独显示 `—`，不会整页崩。

## 主题跟随

```js
el.hass.themes.darkMode            // 首选：读 HA 真实主题
getComputedStyle(...)--card-background-color  // 次选：读父窗口底色
prefers-color-scheme               // 兜底
```

注意：**不要**只用 `prefers-color-scheme`。设备系统深色 + HA 浅色主题是常见组合，会得到"白字压白底"。

另外 iframe 的初始画布在 iOS 上是**白色**，所以页面必须自己画背景色（`html,body{background:...}`），不能指望透明透出 HA 卡片底色。

## 缓存

`/local/` 静态资源带 `Cache-Control: public, max-age=2678400`（31 天）。
改文件必须改 URL 的 `?v=`，否则客户端读旧版。
